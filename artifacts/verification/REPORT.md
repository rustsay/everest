# Проверка «Эвереста» — 17 ноября 2026

Проверена запущенная Docker-версия ветки `new-design`, коммит `05d8a0f`.
Код приложения не изменялся. Проверки выполнялись на отдельных QA-аккаунтах и одном созданном для проверки демо-аккаунте. QA-данные оставлены в локальной БД для воспроизведения; пароли и токены в результатах не сохранялись. Скрипты используют исключительно тестовый пароль.

## Результат

180 автоматизированных проверок ответов и условий: 164 прошли, 16 не прошли. Это количество проверок, а не независимых функций: несколько неудач имеют одну причину. Дополнительно вручную проверены экраны в браузере. Подробные ответы находятся в `results.json`.

Основные сценарии платформы работают. Полностью исправной или готовой к публичному запуску текущую версию назвать нельзя: обнаружены нарушения разграничения доступа и ошибки целостности прогресса.

## Ошибки с приоритетами

### 1. P1 — учитель может изменить оценку чужого ученика

`backend/app/api/teacher.py:139`: обработчик пересмотра проверяет роль учителя, но не принадлежность ученика его классам.

На работе QA-ученика запрос от второго, не связанного с классом QA-учителя вернул **200** и изменил итог. Контрольная проверка карточки того же ученика этому учителю вернула 404, то есть защита реализована непоследовательно.

Нужно проверять доступ к работе до записи оценки.

### 2. P1 — WebSocket доступен без авторизации

`backend/app/api/router.py:289`: подключение `/api/ws/{session_id}` принимается без JWT и проверки владельца. Проверка без токена успешно подключилась к QA-сессии. Канал рассылает этапы обработки, OCR-данные в событиях и результаты/ошибки проверки.

Также `backend/app/api/router.py:176` возвращает статус существующего задания другому пользователю (**200**, `done`). Полный REST-результат при этом защищён и вернул 403.

Нужно проверять владельца и авторизацию для обоих маршрутов, обновив передачу авторизации клиентом WebSocket.

### 3. P2 — повторный пересмотр оценки возвращает 500

`backend/app/api/teacher.py:139`: каждый запрос вставляет новую строку `TeacherReview`, хотя `task_result_id` уникален.

Отдельный первый пересмотр собственным учителем прошёл; повторный вернул **500**. В логах `UniqueViolationError`, ограничение `teacher_reviews_task_result_id_key`. Одна из первоначальных неудач собственного учителя была следствием того, что чужой учитель успел создать пересмотр раньше; отдельная проверка воспроизвела именно повторное сохранение.

Нужны обновление существующего пересмотра и проверка доступа.

### 4. P2 — исправленная учителем оценка не обновляет модель ученика

Тестовый итог изменён с 2/2 на 0/2 через первый допустимый пересмотр, но наблюдение задания T13 осталось **1.0**. Обработчик меняет `judge_decision`, не пересчитывая модель прогресса, прогноз и связанные рекомендации.

Для изолированной проверки первого пересмотра использовалась копия ранее реально проверенного QA-результата в новой QA-сессии. Само распознавание и оценивание в этом дополнительном тесте повторно не выполнялись.

### 5. P2 — новый аккаунт наследует активность демо-ученика

`backend/app/learning/service.py:31`: поверхностная копия `DEFAULT_STATE` сохраняет общие вложенные списки и словари. Демо-инициализация добавляет даты активности в общий список.

Три новых аккаунта 5, 6 и 8 классов сразу получили список активности за **10 предыдущих дней**, в данном процессе также с дубликатами. Это искажает серии посещений; другие изменяемые вложенные значения также требуют изоляции.

Нужна независимая глубокая копия значений по умолчанию при создании и дополнении состояния.

### 6. P2 — нельзя удалить учебник после генерации материалов

`backend/app/api/teacher.py:239`: после генерации конспекта/презентации удаление учебника вернуло **500**. В логах `ForeignKeyViolationError`: `materials_textbook_id_fkey` продолжает ссылаться на учебник.

Учебник без материалов удаляется успешно. Нужно определить поведение: сохранить материалы, отвязав источник, либо явным образом обработать зависимые записи и показать понятное сообщение.

### 7. P2 — прогресс можно менять некорректными данными

`backend/app/api/learning.py:318`: несуществующий блок расписания `fake:0` принят с кодом **200** и проходит обычную логику начисления высоты.

`backend/app/api/learning.py:426`: мини-диагностика принимает **10 правильных ответов из 1**, код **200**. Клиент присылает само число правильных ответов; сервер не проверяет ответы на вопросы.

Нужно проверять существование доступного блока и считать результаты мини-диагностики на сервере. Простого ограничения `ok <= total` недостаточно для защиты результатов.

### 8. P2 — слайд обрезается на узком экране

При ширине текущего окна около **304 px** текст определения выходит за доступную высоту слайда, обрезается и пересекается с подписью бренда. При 1280 px то же содержимое читается нормально.

Снимки: `slides-ui.jpg` и `slides-desktop.jpg`. Нужна адаптивная высота/типографика слайда и проверка переполнения.

### 9. P2 — повреждённая фотография принимается и отправляется модели

Файл `broken.jpg` с произвольными байтами принят с кодом **200**. Декодер возвращает пустой список изображений, но запускаются агенты. В данном прогоне модель запросила отсутствующий скан, парсер JSON упал, результат получил статус `error`; оценка не выставлена.

Нужно проверять успешное декодирование до сохранения задания и вызова модели, возвращая понятную ошибку 400/422.

### 10. P2 — истории разных экзаменов смешиваются

При смене класса/экзамена у одного QA-пользователя история содержит подряд первичные баллы профиля и проценты готовности для базы, ОГЭ и школьной программы. Это видно в карточке ученика: `31 → 96 → 30 → 91 → 97 → 31`.

`backend/app/learning/service.py:78` выбирает историю только по user_id; в таблице измерений нет поля экзамена. Нужна привязка измерений к направлению или явно продуманное поведение при смене профиля.

## Дополнительные ограничения и замечания

- OCR на печатном математическом примере выдал сильно повреждённый текст. В этом прогоне модель правильно прочитала оригинал изображения и выставила 2/2. Это не подтверждает качество распознавания рукописи: рукописные решения в этом наборе не использовались.
- В тесте судьи при расхождении оценок модель ошибочно назвала задание 13 «неравенствами». Возврат корректного JSON и допустимого балла не доказывает методическую правильность. Судья получает заключения экспертов без исходного скана и критериев задания; для качества нужен отдельный набор размеченных работ.
- По коду разрешены 5 файлов на задание, но `get_scan_jpegs` отправляет модели максимум 4 изображения. Это замечание по коду, отдельно пять разных страниц в интеграционном прогоне не проверялись.
- `downloadReportFile` в клиенте поддерживает аргумент `html`, но соответствующий серверный маршрут отсутствует (404). В текущем интерфейсе доступна только кнопка PDF: это не поломка видимой HTML-кнопки.
- Презентация сейчас отображается внутри сайта; отдельный экспорт PPTX не реализован. Разборы — заранее подготовленные анимированные объяснения с озвучкой браузера, а не генерация видео.
- API сохранённых материалов работает, но текущий экран не загружает историю материалов при повторном открытии. Сгенерированный результат исчезает из интерфейса после ухода со страницы, хотя остаётся в БД.
- Озвучка реальным голосом, камера телефона, нативный полноэкранный режим, буфер обмена, нагрузка, восстановление после аварии и качество проверки всех задач 13–19 на реальных рукописных работах не проверялись. Также не оценивалось соответствие всего учебного контента официальным критериям и расписаниям.
