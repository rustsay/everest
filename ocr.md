Как работает
TrOCR — это энкодер-декодер на архитектуре Transformer. Он обрабатывает изображение строки текста через Vision Transformer (ViT), который разбивает картинку на патчи и преобразует их в последовательность. Decoder (текстовый Transformer) генерирует текст посимвольно, используя механизм внимания к визуальным признакам. В отличие от классических OCR, TrOCR не требует отдельного детектора символов — он учит зависимости напрямую.
Код имплементации
from transformers import TrOCRProcessor, VisionEncoderDecoderModel
from PIL import Image
# Загрузка модели и процессора для РУССКОГО рукописного текста
processor = TrOCRProcessor.from_pretrained('microsoft/trocr-base-handwritten')
model = VisionEncoderDecoderModel.from_pretrained('raxtemur/trocr-base-ru-handwritten')
# Загрузка изображения (строка текста!)
image = Image.open('handwritten_line.jpg').convert('RGB')
# Инференс
pixel_values = processor(image, return_tensors="pt").pixel_values
generated_ids = model.generate(pixel_values)
text = processor.batch_decode(generated_ids, skip_special_tokens=True)[0]
print(text)
 
Плюсы
1. Высокая точность на чистых данных: CER ~1.2-1.7% для печатного текста, до 9% для рукописного при правильной сегментации 
2. Работает на уровне человека для разборчивых рукописных текстов 
3. Устойчив к шумам и искажениям — архитектура Transformer обрабатывает вариации 
4. Есть дообученные русскоязычные версии (например, для исторических текстов CER 1.69%) 
 
Минусы
1. Требует предварительной сегментации строк — не умеет сам находить текст на странице (нужен отдельный детектор типа CRAFT) 
2. Падает в точности на грязных данных — без качественной обрезки строк результат сильно ухудшается 
3. Требователен к ресурсам — нужен GPU для приемлемой скорости
4. Русские версии менее протестированы, чем английские
2.PaddleOCR (с русскоязычными моделями)
Ссылки: 
1. https://github.com/PaddlePaddle/PaddleOCR
Как работает
PaddleOCR — это полный пайплайн из трех этапов: детекция (определение областей с текстом), классификация ориентации и распознавание (CRNN с attention). Он использует PP-OCRv4 — легковесную модель с оптимизациями для мобильных устройств. Отдельно существует версия PaddleOCR-VL (мультимодальная), которая объединяет детекцию и распознавание и лучше работает с рукописным текстом.
Код имплементации
from paddleocr import PaddleOCR
# Инициализация с русским языком (модели скачаются автоматически)
ocr = PaddleOCR(    
use_angle_cls=True,   # Определение ориентации текста    
lang='ru',            # Русский язык    ​ocr_version='PP-OCRv4')
# Распознавание с целого изображения (не требует сегментации строк!)
result = ocr.ocr('handwritten_page.jpg', cls=True)
# Формат результата: [[[[x1,y1], [x2,y2], [x3,y3], [x4,y4]], (text, confidence)], ...]
for line in result[0]:    
bbox, (text, confidence) = line    
print(f"Текст: {text}, Уверенность: {confidence:.2f}")
# Объединение всего текста
full_text = '\n'.join([line[1][0] for line in result[0]])
Плюсы
1. Работает "из коробки" с целой страницей — не нужен внешний детектор 
2. Хорошая точность на рукописном тексте (CER ~4.6%) 
3. Русский язык поддерживается официально с предобученными весами
4. Быстрый и легкий — хорошо работает даже на CPU
5. Встроенная обработка ориентации и пост-процессинг
 
Минусы
1. При сравнении на специфических датасетах может уступать TrOCR на 15-20% по точности 
2. Изначально проектировался для печатного текста — рукописный требует настройки 
3. Документация на английском и китайском, русских гайдов мало

4. OCR Transformer (с нуля на кириллице)
Ссылки: 
https://github.com/AniketGurav/ocr-transformer
Как работает
Это кастомная реализация Transformer для OCR, обученная с нуля на кириллических данных. Особенность: в ней можно выбирать feature extractor — либо тяжелый ResNet50 (высокая точность), либо легкую сверточную сеть из 6 слоев (скорость). Перед обучением на реальных данных модель проходит претрейнинг на синтетических данных — слова генерируются на лету с разными шрифтами, фонами и русскими словами .

model.eval()
# Инференс

Плюсы
1. Обучена на реальных русских рукописных данных (33,122 crop'а) 
2. CER ~9% на тестовой выборке — сопоставимо с лучшими моделями 
3. Две версии: heavy (ResNet50, высокая точность) и light (6 сверток, скорость)
4. Полный контроль — исходный код полностью открыт
 
Минусы
1. Сложность интеграции — нет готового pip-пакета, нужно разбираться в структуре
2. Требует предварительной сегментации строк
3. Меньше сообщества и документации по сравнению с PaddleOCR
4. Репозиторий не обновлялся с 2023 года
 

5. handwritten-ocr (Trytonottry)
Ссылка:
https://github.com/Trytonottry/handwritten-ocr
Как работает
Это готовая система, а не просто модель. Она включает:
● Препроцессинг: удаление линовки (линий, клеток), авто-выравнивание (deskew),повышение контраста
● Сегментацию строк
● Распознавание (через обученную модель с поддержкой русского и английского)
● Экспорт в .txt и .docx
Оптимизирована именно для сканов тетрадей, бланков и форм с линовкой .

Плюсы

2. Удаление линовки — критично для тетрадных сканов
3. Работает с многостраничными PDF "из коробки"
4. Поддержка Docker и MIT лицензия 
 
Минусы
1. Меньше гибкости — сложно заменить распознаватель на другую модель
2. Качество распознавания зависит от встроенной модели (не документирована точно)
3. Нет активной поддержки — последние обновления от августа 2025, но проект не массовый

Рекомендация для пайплайна (OCR → LLM):
Быстрый старт: handwritten-ocr — просто положите PDF в папку и получите текст .
Для продакшена: PaddleOCR + дообучение на вашем почерке — лучший баланс точности и скорости .
Максимальная точность: TrOCR с русскими весами (raxtemur/trocr-base-ru-handwritten или taiga75/ru-trocr-1700s ), но потребуется детектор строк .
Основные рекомендации по детекции
 
1. YOLOv8 (armvectores/yolov8n_handwritten_text_detection)
Готовое и очень простое в использовании решение.
Как это работает: Это предобученная модель YOLOv8, специально настроенная на обнаружение строк рукописного текста . Она работает как "детектор", находя на изображении ограничивающие рамки (bounding boxes) вокруг каждой строки.
Плюсы:
1. Простота: Это самое готовое к использованию решение, не требующее сложной настройки.
2. Высокая точность: YOLOv8 показывает отличные результаты на рукописных текстах.
3. Скорость: Очень быстро работает, что критично для обработки больших документов.
Минусы: Может путать строки, если они расположены очень близко друг к другу или имеют сильный наклон.

2. Kraken
Классический и проверенный инструмент для сегментации строк, особенно в исторических документах.
Как это работает: Kraken — это специализированный OCR-движок, который, помимо распознавания, умеет делать "сегментацию строк". Он анализирует изображение страницы и выделяет каждую текстовую строку в отдельный регион .
Плюсы:
Надежность: Отлично справляется со сложными макетами страниц, наклонными и искривленными строками .
Гибкость: Предоставляет тонкий контроль над процессом сегментации.
Минусы: Чуть сложнее в настройке, чем YOLO. Может требовать больше вычислительных ресурсов.
