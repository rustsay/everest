# Спецификация: ИИ-агент для проверки 2 части ЕГЭ по профильной математике

> Версия 1.2 — 2026-05-09

---

## 1. Обзор системы

Веб-сервис принимает сканы рукописных решений заданий 13–19 ЕГЭ по профильной математике, распознаёт текст и запускает мультиагентную проверку с итоговой выставлением баллов.

**Задания:** 13, 14, 15, 16, 17, 18, 19  
**Особые задания:** 14 (стереометрия) и 17 (планиметрия) — чертёж передаётся в VLM как часть оригинального скана, без сегментации.

---

## 2. Выбор OCR-решения

### Рекомендация: PaddleOCR + Hybrid Vision (без YOLOv8)

**Для текста**: **PaddleOCR (PP-OCRv4)**  
Лучший баланс точности и простоты среди всех вариантов. CER ~4.6%, работает с целой страницей без внешнего детектора строк, официальная поддержка русского языка, быстрый на CPU.

**Для чертежей (задания 14, 17) — никакой сегментации**:  
Оригинальный скан целиком передаётся в VLM. Модель видит чертёж в контексте всего решения — это лучше, чем вырезанный фрагмент, потому что геометрические построения и текстовые пояснения к ним связаны.

**Hybrid Vision**:  
OCR плохо справляется с математической нотацией (дроби, корни, показатели степени). Поэтому агентам передаём **и** OCR-текст, **и** оригинальный скан. VLM видит формулы и чертежи напрямую — OCR-текст служит вспомогательным контекстом.

### Почему не другие варианты
| Вариант | Причина отказа |
|---|---|
| TrOCR | Требует внешнего детектора строк (CRAFT/YOLO) — лишний компонент; ниже точность чем PaddleOCR |
| Russian-OCR-API | CER 8-12% — значительно хуже PaddleOCR; словарная постобработка ломает матем. термины |
| OCR Transformer | Высокая сложность интеграции, репозиторий не обновлялся, нет pip-пакета |
| handwritten-ocr | Качество не задокументировано, нет активной поддержки |

## 6. OCR-пайплайн

Единый флоу для всех заданий (13–19):

```
Скан (JPG/PNG/PDF)
    │
    ▼
Препроцессинг (OpenCV)
  - deskew (выравнивание наклона)
  - повышение контраста (CLAHE)
  - удаление линовки (морфологические операции)
    │
    ├──────────────────────┐
    │                      │
    ▼                      ▼
PaddleOCR             Оригинальный скан
(PP-OCRv4, lang='ru')  сохраняется как есть
  - детекция блоков      (передаётся в VLM)
  - распознавание
  - confidence score
    │
    ▼
Постобработка
  - сортировка строк сверху вниз
  - объединение в текст
  - флаг low_confidence если avg < 0.6
    │
    └──────────────────────┐
                           │
                           ▼
             OCRResult {
                 text: str,          ← вспомогательный контекст
                 scan_image: bytes,  ← основной ввод для VLM
                 confidence: float
             }
```

**Для заданий 14 и 17**: никакой отдельной сегментации чертежа не требуется. VLM видит скан целиком — чертёж и текст решения в естественном контексте друг друга.

## 7. Мультиагентная система проверки

### 7.1 Концепция

Имитация реальной проверки ЕГЭ: каждое задание проверяют несколько экспертов независимо.

```
OCRResult + оригинальный скан
           │
           ├────────────────────────────────┐
           │               │                │
           ▼               ▼                ▼
      Agent 1          Agent 2          Agent 3
   (temp=0.3)        (temp=0.7)       (temp=1.0)
   [строгий]         [нейтральный]    [лояльный]
           │               │                │
           └───────────────┴────────────────┘
                           │
                      verdict_1, verdict_2, verdict_3
                           │
                           ▼
                      Judge Agent
                    (temp=0.1 — детерминированный)
                           │
                           ▼
                     Финальный балл
```

### 7.2 Разнообразие агентов

**Вариант A — одна модель, разные температуры** (рекомендуется для начала):
- Agent 1: `temperature=0.3` — строгий, ищет ошибки
- Agent 2: `temperature=0.7` — нейтральный
- Agent 3: `temperature=1.0` — более творческий, лояльный к нестандартным решениям

**Вариант B — разные open-source модели** (если несколько моделей доступны через base_url):
- Agent 1: `Qwen2.5-Math-72B` — специализирован на математике
- Agent 2: `Llama-3.3-70B` — сильная общая модель
- Agent 3: `DeepSeek-R1` — reasoning-модель

Конфигурация выбирается в `config.py` через переменную `AGENT_STRATEGY: "temperature" | "models"`.

### 7.3 Структура вердикта агента

```python
class AgentVerdict(BaseModel):
    task_id: int                    # 13-19
    agent_id: int                   # 1, 2, 3
    score: int                      # 0 до max_score задания
    max_score: int                  # 2, 3, или 4
    reasoning: str                  # Пошаговый разбор решения
    errors_found: list[str]         # Список найденных ошибок
    correct_steps: list[str]        # Правильно выполненные шаги
    confidence: float               # Уверенность агента в своей оценке (0-1)
```

### 7.4 Агент-судья

Получает все три вердикта и выносит финальное решение.

**Логика судьи:**
1. Если все три агента согласны → принять их балл
2. Если двое согласны → принять мнение большинства
3. Если все три дали разные баллы → судья анализирует аргументы и выбирает

```python
class JudgeDecision(BaseModel):
    final_score: int
    reasoning: str                  # Почему выбран именно этот балл
    consensus_level: str            # "full" | "majority" | "judge_decision"
    agent_scores: list[int]         # [score_1, score_2, score_3] для прозрачности
```

### 7.5 Параллельный запуск

```python
async def check_task(task_id: int, ocr_result: OCRResult) -> JudgeDecision:
    verdicts = await asyncio.gather(
        run_agent(agent_id=1, task_id=task_id, ocr_result=ocr_result),
        run_agent(agent_id=2, task_id=task_id, ocr_result=ocr_result),
        run_agent(agent_id=3, task_id=task_id, ocr_result=ocr_result),
    )
    return await run_judge(task_id=task_id, verdicts=verdicts)
```

## 8. Промпт-стратегия

### 8.1 Базовая структура промпта

Каждый агент получает:

```
SYSTEM:
Ты — эксперт ЕГЭ по профильной математике. Твоя задача — проверить решение задания {task_id}
по официальным критериям. Оценивай строго по критериям, без снисхождения.
[Критерии оценивания для конкретного задания]

USER:
## Задание {task_id}
{formulation}

## Распознанное решение (OCR — вспомогательно, могут быть ошибки распознавания)
{ocr_text}

## Оригинальный скан решения
[image: base64]

## Твоя задача
Проверь решение по критериям. При расхождении OCR-текста и скана — доверяй скану.
Верни JSON с полями: score, max_score, reasoning, errors_found, correct_steps, confidence.
```

### 8.2 Специфика по заданиям

| Задание | Тема | Max балл | Особые инструкции в промпте |
|---|---|---|---|
| 13 | Уравнение / неравенство | 2 | Проверить ОДЗ, равносильность переходов |
| 14 | Стереометрия | 3 | VLM видит чертёж в скане; проверить вспомогательные построения |
| 15 | Экономическая задача | 3 | Проверить составление уравнения по условию |
| 16 | Тригонометрия | 4 | Проверить каждое преобразование; ОДЗ для тrig. уравнений |
| 17 | Планиметрия | 4 | VLM видит чертёж в скане; проверить теоремы на которые ссылается |
| 18 | Задача с параметром / текстовая | 4 | Строгая проверка разбора на случаи |
| 19 | Теория чисел | 4 | Проверить полноту перебора, доказательство невозможности |

### 8.3 Промпт судьи

```
SYSTEM:
Ты — главный эксперт ЕГЭ. Три независимых эксперта проверили одно решение
и дали следующие оценки. Твоя задача — вынести финальный справедливый вердикт.

USER:
Задание {task_id}, максимальный балл: {max_score}

Эксперт 1 (строгий): {score_1}/max — {reasoning_1}
Эксперт 2 (нейтральный): {score_2}/max — {reasoning_2}
Эксперт 3 (лояльный): {score_3}/max — {reasoning_3}

Верни финальный балл и объяснение. JSON: final_score, reasoning, consensus_level.
```

## 9. Авторизация

JWT-based аутентификация. Токен живёт 30 дней, хранится в `localStorage`.

### Endpoints

| Method | Path | Описание |
|---|---|---|
| POST | /api/auth/register | Email + password → JWT |
| POST | /api/auth/login | Email + password → JWT |

Все остальные endpoints требуют заголовок `Authorization: Bearer <token>`.

### DB-схема пользователей

```sql
users        (id, email UNIQUE, password_hash, created_at)
sessions     (id UUID, user_id FK, created_at)
task_results (id, session_id FK, task_id, status, ocr_text, ocr_confidence,
              agent_verdicts JSONB, judge_decision JSONB, error, updated_at)
              UNIQUE(session_id, task_id)
```

Таблицы создаются автоматически при старте через `Base.metadata.create_all`.

### История проверок

`GET /api/sessions` — возвращает все сессии пользователя с суммарными баллами по каждому заданию. Фронтенд показывает историю на главной странице после логина.

## 10. API спецификация (Backend)

Все endpoints ниже требуют `Authorization: Bearer <token>`.

### POST `/api/sessions`
Создать сессию проверки.  
Response: `{ session_id: uuid }`

### POST `/api/sessions/{session_id}/tasks/{task_id}/upload`
Загрузить скан задания (task_id: 13-19).  
Body: `multipart/form-data` с полем `file` (JPG/PNG/PDF).  
Response: `{ task_id, status: "processing", upload_id: uuid }`

### GET `/api/sessions/{session_id}/tasks/{task_id}/status`
Статус обработки задания.  
Response: `{ status: "pending|ocr|checking|done|error", progress: 0-100 }`

### GET `/api/sessions/{session_id}/results`
Итоговые результаты всей сессии.  
Response:
```json
{
  "session_id": "...",
  "total_score": 15,
  "max_total": 26,
  "tasks": [
    {
      "task_id": 13,
      "final_score": 2,
      "max_score": 2,
      "consensus_level": "full",
      "agent_scores": [2, 2, 2],
      "reasoning": "...",
      "ocr_text": "...",
      "figure_detected": false
    }
  ]
}
```

### WebSocket `/ws/sessions/{session_id}`
Стриминг событий обработки в реальном времени.  
Events: `ocr_started`, `ocr_done`, `agents_started`, `agent_done`, `judge_done`, `task_complete`

## 13. Открытые вопросы и решения

| Вопрос | Рекомендуемое решение |
|---|---|
| OCR плохо читает формулы | Hybrid: передавать оригинальный скан vision-модели вместе с OCR-текстом |
| Как обрабатывать чертежи в задании 14/17 | Передавать весь скан в VLM — модель видит чертёж в контексте решения |
| Какой LLM для продакшена | Qwen2.5-Math-72B как Agent 1 — специализирован на математике |
| Итоговый балл: max или судья | Судья → честнее; max → лояльнее к ученику. Оставить как конфигурацию |
| Что если скан плохого качества | OCR вернёт low_confidence → предупредить пользователя и попросить переснять |
| Стоимость API-вызовов | 3 агента + судья = 4 вызова на задание × 7 заданий = 28 вызовов на сессию |
