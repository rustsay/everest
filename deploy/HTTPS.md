# HTTPS без домена: 144.31.194.150

Основной `docker-compose.yml` запускает собранный фронтенд в Nginx.
При `HTTPS_ENABLED=true` он также выпускает бесплатный сертификат Let's Encrypt
на публичный IPv4 и продлевает его. По умолчанию HTTPS выключен:
локально Certbot не обращается в Let's Encrypt и не меняет сертификаты.

Нужны Docker Engine и Docker Compose v2 на сервере `144.31.194.150`.
TCP-порты **80 и 443** должны быть свободны и доступны из интернета:
проверь firewall сервера и правила сети в панели хостинга.
Если их занимает ранее установленный Nginx/Apache, сначала перенеси его
конфигурацию или освободи эти порты; второй сервер на них не запустится.

## Первый запуск

В каталоге проекта на сервере сохрани текущий `.env` с настройками приложения.
На сервере добавь в `.env` `HTTPS_ENABLED=true`.
IP `144.31.194.150` уже задан по умолчанию; контактная почта необязательна:

```dotenv
HTTPS_ENABLED=true
HTTPS_IP=144.31.194.150
LETSENCRYPT_EMAIL=your-email@example.com
```

Почту можно не указывать: регистрация в Let's Encrypt работает и без неё.
Если указываешь почту, замени пример на свою. Если `.env` ещё нет, создай его из `.env.example`
и заполни настройки приложения. Не перезаписывай существующий `.env`.
В локальном `.env` оставь `HTTPS_ENABLED=false` или не указывай этот параметр:
сайт будет доступен по `http://localhost`, без редиректа на серверный IP,
даже если в томе уже есть сертификат. Также сохраняется доступ через
`http://localhost:3000`. С другого устройства можно использовать IP машины
с портом 3000 или без порта.

Запусти:

```bash
docker compose up -d --build
docker compose logs -f certbot frontend
```

При первом запуске сайт доступен по `http://144.31.194.150`.
Certbot подтверждает контроль IP через `/.well-known/acme-challenge/`,
получает сертификат, и Nginx в течение 30 секунд включает HTTPS и редирект.
После успешного выпуска открой **https://144.31.194.150** без порта.
Если выпуск не удался, сайт остаётся на HTTP, а Certbot повторяет попытку
через 5 минут; причина видна в логах `certbot`.

Контейнеры используют то же имя проекта и существующие тома БД и загрузок,
что и раньше. HTTP опубликован на портах 80 и 3000, HTTPS — на 443.
Оба HTTP-адреса после выпуска сертификата перенаправляют на HTTPS без порта.
Фронтенд, API, WebSocket и загрузки работают через Nginx на одном адресе;
порт 8000 на хосте не публикуется.

## Продление и обновление проекта

IP-сертификат действует около 6 дней. Контейнер `certbot` проверяет необходимость
продления каждые 12 часов. Nginx замечает изменение сертификата и перечитывает
его без остановки сайта. Порт 80 должен оставаться доступным для продления.
После перезагрузки сервера контейнеры запускаются снова автоматически.
Сертификаты и ключи хранятся в отдельном Docker-томе `letsencrypt`.
Не используй `down -v`: эта команда удаляет постоянные тома, включая БД.

Для обновления исходников используй ту же команду запуска:

```bash
docker compose up -d --build
```

Проверка процесса продления через тестовый сервер Let's Encrypt
(рабочий сертификат не заменяется):

```bash
docker compose exec certbot \
  certbot renew --dry-run --cert-name 144.31.194.150
```

Проверить ответ сайта:

```bash
curl -I https://144.31.194.150
```

При смене IP укажи новый `HTTPS_IP` в `.env` и снова запусти Compose.
На новом IP также должны быть доступны порты 80 и 443.

Используется Certbot 5.4 с поддержкой IP и проверки через webroot:
[инструкция Let's Encrypt](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).
