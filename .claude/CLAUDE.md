# ЕГЭ Checker — Project Guide

«Эверест» - подготовка к экзаменам по математике (ЕГЭ профиль и база, ОГЭ). 5-8 и 10 классы с ноября 2026 убраны: при регистрации
и в профиле только 9 и 11 класс (`api/learning.GRADES`); старые аккаунты 5-8 / 10 выбирают класс заново (`needs_profile`).
Контент `g10` и `g58` в `learning/content.py` пока лежит, но недоступен.
Ядро - автоматическая проверка 2 части ЕГЭ профиль (задания 13–19) по фото: мультиагентная проверка через OpenAI-совместимый LLM API.
Вокруг неё (ветка `new-design`): необязательная входная диагностика, образовательная траектория (ИИ или правила; в классе утверждает учитель), прогноз балла, карты заданий 1-19 с первопричиной, расписание до экзамена,
банк задач для ученика и учителя, варианты учителя из банка,
задача дня, звёзды и высота, помощник, разборы заданий, кабинет учителя, конспекты и презентации по учебникам.

## Быстрый старт

```bash
cp .env.example .env       # заполнить LLM_BASE_URL, LLM_API_KEY, LLM_MODEL, SECRET_KEY
docker compose up --build  # поднимает backend + frontend + postgres
```

- Frontend: http://localhost:3000
- Backend API: http://localhost:8000/api
- Swagger docs: http://localhost:8000/docs

## Архитектура

```
frontend (React + Tailwind)  →  nginx  →  FastAPI backend  →  LLM API (OpenAI-compatible)
                                                          ↕
                                                    PostgreSQL
                                                    (сессии, результаты, юзеры)
                                                          ↕
                                                    /app/uploads volume
                                                    (scan files)
```

## WebSocket события

```
ocr_started       → task_id
ocr_done          → task_id, confidence, low_confidence
agents_started    → task_id
agent_done        → task_id, agent_id, score
judge_done        → task_id, final_score
task_complete     → task_id, final_score, max_score
task_error        → task_id, error
```

## Мультиагентная проверка

3 агента запускаются параллельно через `asyncio.gather`:
- Agent 1: temperature=0.3 (строгий)
- Agent 2: temperature=0.7 (нейтральный)
- Agent 3: temperature=1.0 (лояльный)

Судья вызывается **только** если все 3 дали разные баллы (при консенсусе 2/3 — экономия LLM-вызова).
Итого ≤28 LLM-вызовов на полную сессию (7 заданий × 4 вызова макс.).
Максимальный балл: 20 (13:2 + 14:3 + 15:2 + 16:2 + 17:3 + 18:4 + 19:4).

Каждому агенту передаётся: системный промпт + критерии задания + OCR-текст + оригинальный скан (base64).
VLM видит формулы и чертежи напрямую; OCR-текст — вспомогательный контекст.

## Переменные окружения (.env)

| Переменная | Описание |
|-----------|----------|
| LLM_BASE_URL | URL OpenAI-совместимого API |
| LLM_API_KEY | API ключ (любая строка если не требуется) |
| LLM_MODEL | Название модели, например `google/gemma-4-26b-a4b-it` |
| POSTGRES_PASSWORD | Пароль PostgreSQL (default: postgres) |
| SECRET_KEY | Секрет для JWT подписи — **сменить в продакшене** |
| EMAIL_CONFIRM | Код из письма при регистрации (по умолчанию true) |
| SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM | Почта для кодов; порт 465 - SSL, иначе STARTTLS. Пусто - код в логе backend |

## Заметки по реализации

- OCR (PaddleOCR) — синхронный, запускается в thread pool через `run_in_executor`
- Сканы хранятся в Docker volume `/app/uploads` (не в БД — слишком большие)
- Результаты в PostgreSQL: таблицы `users`, `sessions`, `task_results` (JSONB для вердиктов)
- Таблицы создаются автоматически при старте через `Base.metadata.create_all`; новые колонки `users`
  (name, role, grade, exam, is_demo) добавляются в существующую БД через `ALTER TABLE … IF NOT EXISTS` в `init_db()`
- Таблицы нового дизайна: `learner_states` (JSONB-документ ученика), `diagnostics`, `measurements` (история прогноза),
  `notifications`, `chat_messages`, `class_groups`, `class_members`, `assignments`, `teacher_reviews`, `textbooks`, `materials`,
  `task_files` (файлы к прототипам, сами файлы в `/app/uploads/taskfiles`), `bank_problems` (банк задач: draft/approved),
  `skill_explanations` (кэш объяснений: умение × учебник)
- Карта задания: процент прототипа = доля верных первых попыток по его задачам + задание этого номера из диагностик
  и пробников (`TASK_MAPS[n]["diag"]` связывает вариант диагностики с прототипом). Ответы `state.data["tm"]`.
  Карты готовы для 1-19 (прототипы и умения согласованы с методистом). Задачи: свои у задания 1 + опубликованные из банка.
  Ученику коды кодификатора не показываются, умения сформулированы как действия.
- Объяснение умения: учебники учителя (ученику - учителей его классов) → `textbook_search.best_pages` по ключевым словам →
  LLM пишет только по этим страницам со ссылками «стр. N» (PDF хранится с метками [[стр. N]]); нет страниц → без LLM, честное «не нашлось»
- Банк задач: импорт ничего не публикует; для 1-12 ответ обязателен, для 13-19 задача без ответа решается через проверку по фото
- Диагностика необязательна (`engine.diag_required` → False): после регистрации её предлагают один раз, можно пропустить.
  Пока её нет, `dashboard.diag_done = false`, и главная вместо прогноза показывает приглашение пройти диагностику
- Маршрут и расписание строятся правилами `engine.build_plan`, без LLM. Первая попытка задачи с коротким ответом
  (карта задания, банк, вариант учителя) идёт в `state.data["prac"]` (T{n} → [верно, всего]) и подмешивается к оценке задания:
  вес 0.6·k/(k+2) при k ответах, с проверкой по фото - пополам с её результатом. Темы под заданиями, где 2+ ответа и меньше
  половины верных, встают в очередь тем раньше. `route_basis` (diag/practice/start) - на чём держится маршрут,
  клиент честно пишет «Стартовый маршрут», пока данных нет
- Траектория (`learning_paths`): этапы {title, from, to, goal, tasks[T{n}], check, problems[ref]}. ИИ (`llm.build_path`) получает
  только факты (оценки заданий, ответы, ошибки проверки по фото, даты) и id заданий; `paths.validate` выбрасывает чужие id,
  обрезает даты до экзамена и убирает наложения; задачи этапов подбирает сервер из банка. Нет ИИ или плохой ответ → `rules_path`.
  Статусы: draft (учитель) → active; pending (ученик в классе) → active / rejected. Ученик без класса: сразу active, `path_follow`.
  Расписание: во время этапа его задания в 3 раза чаще (`build_plan(stages=…)`), `route_basis = "path"`. Траектория класса
  действует у учеников без своей. Старая траектория по одной сессии проверки (`agents/trajectory.py`) осталась, дата экзамена исправлена
- Задачи адресуются ссылками: `s1:r2` - встроенная задача задания 1, `f57` - задача открытого банка ФИПИ, `b12` - задача банка (`learning/problems.py`).
  Ученик получает задачи без ответов; решение видно после первой попытки
- Ключи ответов диагностики хранятся только на сервере (`learning/content.py`), клиент получает задания без них
- После проверки по фото `api/router.py` вызывает `learning.service.on_task_checked`: балл обновляет оценку
  самого задания (`obs`, вес 60% в прогнозе), а через неё прогноз и расписание; освоение тем на карте не меняется.
  Точка на графике появляется только после диагностики
- Логика модели в `learning/engine.py` без БД и сети: её удобно проверять обычными вызовами функций
- JWT токен живёт 30 дней, хранится в localStorage

## Общая загрузка фото и разбор своей задачи

- `api/batch.py` и `components/WorkUpload.tsx`: общая загрузка фотографий, предложения номеров 13–19,
  ручная корректировка и подтверждение перед проверкой. Прежняя загрузка по заданиям сохранена.
- `api/videos.py` (историческое имя API `/api/videos`) и `video/steps.py`: генерация JSON-шагов,
  история пользователя в `generated_videos`; новые разборы не создают MP4/MP3.
- `components/SolutionBoard.tsx` используется и типовыми, и своими разборами: зелёная доска,
  пояснения Звёздочки, пауза, скорость и список шагов. Маршрут своего разбора: `#video/custom-{id}`.
- Вся озвучка (`utils/speech.ts`, `api/speech.py`, POST `/api/speech`) использует edge-tts,
  женский `ru-RU-SvetlanaNeural`, темп `-6%` из исходного генератора. Нужен доступ к сервису Microsoft.
  Аудио возвращается авторизованному пользователю; ограниченный кэш в памяти (32 МБ, до 128 записей),
  текст и аудио не пишутся на диск. Выключение голоса, смена страницы и пауза отменяют проигрывание.
  Доска ждёт завершения записи шага и озвучки; скорость меняет также темп проигрывания.
  Следующие две реплики загружаются заранее; браузер кэширует MP3 (до 16 МБ / 64 записей),
  сервер объединяет одновременные запросы одной реплики и повторяет временный сбой до трёх попыток.
  Анимация доски начинается с реальным воспроизведением; при ошибке шаг останавливается для повтора.
  Закрытие пузыря останавливает только канал `mascot`, не текущий `board`; таймер пузыря снимается при замене сообщения.
  Смена скорости меняет playbackRate текущей записи без её перезапуска.
- OCR-модели сохраняются в volume `ocr_models`; инициализация и вызовы общего predictor защищены блокировкой.
- Локальные отчёты и снимки проверок находятся в `artifacts/verification/` и не отслеживаются Git.

## Диагностика, цель, расписание (ноябрь 2026)

- Диагностика: в 1 и 2 части к каждому заданию фото решения или «Не знаю»; «Решил устно» только у № 8. Пропусков нет:
  `finish` отвечает 400 со списком заданий, 409 пока ИИ разбирает фото. Фон `diag_work._analyze`: 1 часть - `llm.analyze_short`
  (способ верный → ошибка в счёте), 13-19 профиля - OCR + 3 агента, ОГЭ - `llm.grade_long`. Без ИИ фото не даёт данных.
  Запись ответов под `asyncio.Lock` на диагностику (один процесс uvicorn).
- `engine.eval_item`: верно и способ верный → 1; верно без способа → 0.4; неверно, но способ верный → 0.7 знания темы и 0.35 шанса;
  «Не знаю» → 0. Всё неверно → прогноз 0 и `basics` (первопричина - основы, не «логарифмы»).
- Цель: `content.PROF_SCALE_2026` (шкала 2026 по Lenta.ru, официальной Рособрнадзора не нашли) → `needed_tasks` (85% максимума).
- `build_plan`: дни по блокам (геометрия / алгебра / вероятность / функции), от простого к сложному (`base_topic` спускается к слабой
  основе), прототипы по порядку, вторая часть закрыта до `part2_open` (есть балл во 2 части или 1 часть ≥ 0.7). Этап траектории сужает задания.
- Траектория собирается сама (`auto_build`) после диагностики и после выбора цели; `rules_path` - этапы по блокам с шагами.

## Банк ФИПИ, разборы, кабинет учителя

- Открытый банк ФИПИ: `tools/fipi_import.py <pdf>` режет PDF-сборник банка на картинки задач и ответов,
  текст только для поиска и ИИ. Прототип карты - по теме сборника и словам условия (`fipi._proto`). Задачи ФИПИ видны
  в «Банке задач», на картах заданий, в вариантах, траекториях и разборах; ответы 1-12 проверяются, 13-19 - по фото.
- Разборы (#video): вкладки 1-19, типовой разбор + задачи банка «Разбор на доске» (`#video/p-<ref>`). Для картинок ФИПИ
  `generate_steps` получает картинку условия и ответа; без ИИ разбор строится только из решения банка.
- Конспекты и презентации: страницы учебника (`pages: "112-118"`, номера страниц файла PDF), без них страницы ищутся по теме;
  ИИ может дополнить (помечено «Дополнение:»). Слайды: kind, formula, fig (`llm.SLIDE_FIGS` = ключи `GeoFig`), печать в PDF.
- Учебники и банк принимают .docx (текст и формулы Word; формулы-картинки теряются).
- Карточка ученика у учителя: прогноз, цель, траектория, по заданиям (оценка, диагностика, банк, фото), ошибки проверок, ответы диагностики, варианты.
- Помощник учителя: в контексте ошибки проверок учеников и до 3 страниц учебников учителя по вопросу (`textbook_search.search_books`).

## Аналитика, проверка 1 части, работа над ошибками, пробник, итоги недели

- Аналитика (`learning/analytics.build`) сохраняется в `diagnostics.result.analytics` при `finish`: строки по заданиям
  (kind: ok, ok_doubt, slip, method, wrong, dont_know, none, full, part, zero, unchecked), счётчики, блоки, `gains`
  (сначала ошибки в счёте), советы, факты. Вывод Звёздочки (`llm.diag_summary`) пишется только по фактам, без ИИ его нет.
  Во время диагностики вердикт по фото не показывается (`public_work` отдаёт только технические ошибки).
- Проверка 1 части: с задачей банка ответ решает ключ, ИИ (`analyze_short`) смотрит способ; первая попытка идёт на карту
  задания. Своя задача: `check_short_nokey`, ученику честно пишется «без ключа».
- Работа над ошибками (`service.redo_*`, `state.data["redo"]`): неверная первая попытка (карта, банк, вариант, проверка
  1 части, разбор до решения) → через 3 дня, верно → через 7, ещё раз верно → закрыта (+40 м); неверно → снова 3 дня.
- Пробник «как на экзамене»: `answers["_exam"] = {start, limit}` (профиль и ОГЭ 235 мин, база 180). Любой порядок, пустые
  задания = не решено, в 1 части достаточно ответа. После конца времени (+90 с) ответы не принимаются, можно только сдать.
- Итоги недели: дневные счётчики `state.data["days"]` (`service.count`: solved, ok, checks, checks1, fixed).
  `weekly_loop` в lifespan раз в час: с понедельника 9:00 уведомление ученику и письмо родителю (если SMTP и почта есть),
  один раз за неделю (`report_week`). Один процесс uvicorn, иначе письма задвоятся.
- Помощник принимает до 5 фото и 3 файлов (PDF, DOCX, TXT; скан PDF уходит картинками, до 8 картинок), ученик и учитель.

## Траектория и расписание под себя

- Ученик правит траекторию (`PUT /path/mine`): те же проверки, что у ИИ (`paths._edited` → `validate`). Один - новая версия
  сразу active; в классе - pending с `data.student_edit.comment`, прежняя active действует до утверждения.
  Метки: `student_edit` - «изменено учеником», `edited` ставит только правка учителя.
- Совет по траектории (`llm.path_advice`): результаты по заданиям + черновик, правила хорошей траектории, только совет.
- Свои дела (`state.data["events"]`, до 30): `engine.day_events` кладёт их в дни расписания; `busy` - математики в этот день нет,
  очередь сдвигается; больше 5 часов занятий в день - `heavy`. Дни математики `plan.wd` (любые из Пн-Вс; выбор числа дней
  сбрасывает `wd`), время `plan.time` только для показа.

## Установка на телефон, push-уведомления, админка (ноябрь 2026)

- PWA: `frontend/public/manifest.webmanifest`, значки `public/icons` (рисунок логотипа), `public/sw.js`. Service worker только
  показывает уведомления и открывает `/#go` по нажатию; страницы не кэширует. `src/pwa.ts`: регистрация, кнопка установки

- Web Push без сторонних библиотек: `app/webpush.py` (VAPID ES256 + шифрование aes128gcm по RFC 8291), проверено на примере
  из RFC 8291, Appendix A (`tests/test_webpush.py`). Запросы уходят только на адреса сервисов браузеров (`PUSH_HOSTS`).
- `api/push.py`: таблица `push_subscriptions`. Каждый `service.notify` после commit уходит и push (`queue_push` + событие

- Учёт активности: middleware в `main.py` → `activity.track` (id из токена, раздел по пути `SECTIONS`, опросы статуса не считаются)
  → буфер → `user_activity` (user_id, day, hits, sections) раз в минуту. Хранятся только счётчики, без содержимого.
- Админка (#admin, `pages/Admin.tsx`, `api/admin.py`): доступ по `ADMIN_EMAILS` (`auth.deps.require_admin`, `me.admin`).
  Пользователи и активные за день / 7 / N дней, графики по дням, путь ученика (регистрация → профиль → диагностика →
  задачи → 3 дня → заходил за неделю), разделы, действия за период (таблицы + счётчики `state.data["days"]`), список
  пользователей с поиском. Демо не считается.

  диагностики остаются «одна задача на номер», `engine.items_of` выбирает формат). Первая часть: все типы карт заданий 1-12 по порядку

  перерешаны вручную, свои - ещё и перебором. Для 14.1 и 18.8 задачи банка выбраны вручную: автоматическое отнесение к типу там ошибалось.

  картах заданий берутся из типов (`api/taskmaps._diag_entries`).

## Траектория профиля по методике (ноябрь 2026)

- `learning/method.py` (чистые функции): модули с неделями и часами (`MODULES`), планы 1-3 (`PLANS`), требования перед модулем,
  ожидаемый результат (`EXPECT`). План выбирается по `state["types"]`: доля решённых типов 1-12 ≥ 0.9 (`GOOD_PART1`) → план 2,
  ещё и полный балл за выбранный тип 13, 15, 16 → план 3, иначе план 1. Цель от 82 (`HIGH_TARGET`): модуль 1-12 не больше 4 недель.
  Часов в неделю меньше, чем по методике (дни × минуты), - модуль растягивается (часы / часы в неделю); что не влезает до экзамена
  минус 5 недель повторения (`REVIEW_WEEKS`), отрезается с конца, ожидаемый результат снижается на баллы отрезанных заданий по шкале 2026.
  Осталось время - добавляются 19, 18, 14 (`EXTRA_ORDER`). Перед 17 и 14 в планах 2-3 вставляется неделя «Все типы № 1 (и № 3)»,
  если в диагностике они не все решены; она идёт в паре со своим модулем.
- `api/paths._build`: для профиля траектория всегда по методике (`source = "method"`, блок `method`: план, ожидаемый результат,
  часы в неделю, что отрезано); для базы и ОГЭ - как раньше (ИИ или правила). Этапы хранят `module`, `hours`, `weeks`, `links`
  (разборы `video/t{n}`), `validate` их сохраняет, задач в этапе до 12.
- Расписание: задания текущего этапа берутся, даже если вторая часть ещё «закрыта»; прототипы идут от слабого типа (`_protos_by_types`:
  решённые типы в конец). Совет Звёздочки по траектории знает правила методики (`llm.METHOD_RULES`).

  «Повторение и пробники» тянется до экзамена. Сохранение - через `PUT /path/mine`: один - сразу, в классе - учителю на утверждение.

## Приглашение по ссылке, «Мои материалы», презентации (ноябрь 2026)

- Ссылка класса: `/?join=КОД` (кнопка «Ссылка для учеников» в кабинете; на телефоне - меню «Поделиться»). `src/invite.ts` при загрузке

  После входа или регистрации `App.route` вступает в класс (`/classes/join`; повторное вступление не шлёт учителю уведомление). Демо код сбрасывает.
- Материалы сохраняются всегда (`materials`); страница «Конспекты и презентации» показывает «Мои материалы»: открыть, переименовать,
  править текст конспекта и слайды, удалить. Удаление учебника не удаляет материалы (`textbook_id` → null).
- Презентации (`components/Deck.tsx`): слайды по видам (title, goal, def, theorem, example со `steps`, task, quiz с `question`/`answer`,
  exam, summary), `llm.clean_slide` проверяет и слайды ИИ, и правку учителя. Оформления `THEMES`: everest, board (доска, мел), paper (тетрадь),
  night; хранится в `content.theme`. Размеры в cqw, длинный текст уменьшается сам (`--k`). Показ `SlideShow`: пункты, шаги, ответ, формула,
  рисунок появляются по щелчку (пробел, стрелки, пульт PageDown), переходы между слайдами, N - заметки, B - тёмный экран, таймер, свайп.
  Печать в PDF - все слайды в выбранном оформлении. `prefers-reduced-motion` выключает анимацию.
